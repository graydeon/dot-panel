# Skills framework release candidate

The `1.0.0-rc.1` installer contains five discoverable skills, original branding, an optional owner-run local usage helper and sanitized retained source pinned to `55b19217d08f33c01e18b51609d1685212aa1c67`. It has a portable root `plugin.json` plus a Codex compatibility manifest. It does not distribute a shared MCP endpoint or a private Site identity. Each user's dot needs available Sites tools and creates/connects that user's own private panel.

Build with `python3 scripts/package-plugin.py --output /absolute/output/directory` (Python 3.10+, `jsonschema==4.26.0`, Git and the pinned source history required). The builder uses tracked source from that commit, not local app state, and deterministic sorted ZIP entries with fixed timestamps. It validates safe regular paths, the published portable schema, field limits, source/resource hashes, skill links, original assets and privacy patterns. See [the manifest](../packaging/plugin.json), [install guidance](../packaging/INSTALL.md) and [recorded exact-package evidence](../packaging/validation-rc.1.json).

Clean install, audit, domain/widget/recovery/helper/runtime tests and generic/Sites builds passed from the exact extracted ZIP template. Two rebuilt ZIPs were byte-identical. Codex CLI 0.147.0's read-only `plugin/read` recognized the exact local candidate's version, original icon/listing and five namespaced skills through a temporary explicit marketplace. It reported **installed: false**. No model turn, account read, personal plugin installation or marketplace/config mutation was performed. This is native discovery evidence, not an installed-user workflow or portal acceptance.

Publisher metadata uses the verified public GitHub handle `graydeon`. The owner must choose the actual verified portal identity and reconcile it if different. The support URL is the real repository's issues page; [the data-handling notice](privacy.md) covers the bundled software without claiming control over platform retention. No fictitious support domain, legal identity or MCP endpoint is supplied. The portal's metadata/skill checks, skills-only listing eligibility, fresh-user installation, independent users/devices and eventual public review remain external gates. Skills-only packages do not require MCP review cases/video; generated private Site plugins are separate connections. Do not submit, publish or tag v1 based on ZIP validation alone.

Official references: [package format](https://developers.openai.com/plugins/build/plugins), [guidelines](https://developers.openai.com/plugins/plugin-guidelines), [submission](https://developers.openai.com/plugins/deploy/submission), [portable schema](https://agent-plugins.org/schemas/1.0.0/plugin.schema.json).
